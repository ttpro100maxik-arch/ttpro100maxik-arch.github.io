# Дзен через RSS: сайт + лента «Просто Максик»

Статьи Сценариста превращаются в маленький сайт (GitHub Pages) и ленту `rss.xml`.
Дзен сам забирает ленту и публикует статьи в канал. Ручная постановка в Студии не нужна.
Всё бесплатно (правило 0): GitHub бесплатно, Python без внешних библиотек.

## Как это устроено

```
content/<папка>/дзен-*.md   (пишет Сценарист)
        │  build.py  (локально, на Mac)
        ▼
data/articles.json + data/img/          ← все статьи, включая будущие
        │  render.py  (GitHub Actions, 08:00 и 19:00 МСК)
        ▼
docs/index.html, docs/a/<slug>.html, docs/img/, docs/rss.xml   ← только вышедшие
        │  GitHub Pages
        ▼
https://<логин>.github.io/rss.xml  →  Дзен
```

- Статья «вышла», когда время МСК ≥ времени слота из шапки (`ДЗЕН · 29.10 · 08:00 · …`).
- Пока статья не вышла, её нет ни на сайте, ни в ленте, ни её картинок.
- В ленте только статьи за последние 7 дней (Дзен старше всё равно не берёт), `pubDate` = время слота.
- Блоки `VK · …` в файлах игнорируются.
- Если рядом с картинкой есть версия `-v2` (например `…-fonarshchik-ii-v2.jpg`), берётся она (`prefer_v2_images`).

## Файлы

| Файл | Что делает |
|---|---|
| `config.json` | адрес сайта, метатег Дзена, категория, окно ленты, откуда брать статьи |
| `build.py` | разбирает md → `data/articles.json`, копирует картинки в `data/img/`, пишет `data/missing-images.txt` |
| `render.py` | собирает `docs/` на текущий момент (`--now` для проверки) |
| `validate.py` | проверяет ленту и сайт по требованиям Дзена, код 1 при ошибках |
| `.github/workflows/release.yml` | 05:00 и 16:00 UTC (08:00 и 19:00 МСК) + ручной запуск: render → validate → коммит `docs/` |
| `tests/` | `python3 -m unittest discover -s tests -v` |

## Настройки `config.json`

- `base_url` — адрес сайта со слешем в конце, например `https://prostomaxik.github.io/`.
- `dzen_verification_meta` — метатег из Дзена целиком (`<meta name="…" content="…"/>`) или только значение `content`. Попадает в `<head>` каждой страницы.
- `verification_files` — если Дзен предложит проверку файлом: `{"имя-файла.html": "содержимое"}`, файл появится в корне сайта.
- `categories` — категории каждой статьи, по умолчанию `["native-yes"]`. Для черновиков в Студию: `["native-draft"]`.
- `feed_days` — окно ленты, 7.
- `feed_from` — статьи раньше этой даты не попадают в ленту (сайт их показывает). Нужно, чтобы не задвоить то, что уже выложено руками. Пример: `"2026-10-29T00:00"`.
- `exclude_ids` — точечно убрать статьи из ленты, id вида `2026-10-28-0800`.
- `sources` — где искать md-файлы (относительно папки конфига).
- `inner_image_caption` — подпись под картинкой внутри статьи («Иллюстрация создана ИИ»).

## Что Макс делает сам (только он, не чаты)

1. **Аккаунт GitHub.** Зарегистрироваться на github.com. Логин станет адресом сайта: `логин.github.io`. Кириллические домены Дзен не принимает, github.io подходит.
2. **Репозиторий** с именем ровно `<логин>.github.io`, публичный (бесплатный Pages работает только с публичными).
   Почему так: Дзен требует, чтобы домен ленты совпадал с доменом подтверждённого сайта. У «пользовательского» репозитория сайт живёт в корне домена `https://<логин>.github.io/`, лента — `https://<логин>.github.io/rss.xml`. Если взять обычный репозиторий, адрес будет `https://<логин>.github.io/<репо>/` — домен тот же, но подтверждение «Своего сайта» по метатегу ищется на главной странице домена, а её там не будет. Поэтому только `<логин>.github.io`.
3. **Залить туда содержимое папки `tools/dzen-rss/`** (вместе с `data/` и `.github/`). Это делает Макс или чат с его «ок» в чате (правило 11: выкладка = публикация).
4. **Settings → Pages:** Source «Deploy from a branch», ветка `main`, папка `/docs`.
5. **Settings → Actions → General → Workflow permissions:** «Read and write permissions» (иначе робот не сможет коммитить `docs/`).
6. Вписать в `config.json` свой `base_url`, запустить вручную **Actions → release → Run workflow**, открыть `https://<логин>.github.io/` — главная должна открыться.
7. **Дзен-студия → «Свой сайт»:** добавить `https://<логин>.github.io/`, выбрать проверку метатегом, вставить его в `config.json` → `dzen_verification_meta`, залить, снова Run workflow, нажать «Проверить» в Дзене.
8. **Ленту отправлять только после того, как `python3 validate.py` пишет «ИТОГ: OK»** и в ленте уже есть несколько готовых статей с обложками. Проверок ленты у Дзена около трёх в год, при отказе по содержанию следующая попытка через 6 месяцев. Нужен канал минимум с 10 подписчиками.
9. Перед отправкой решить про задвоение: статьи, уже выложенные руками в Студии (27.10 19:00, 28.10 08:00 и 19:00), убрать из ленты через `feed_from` или `exclude_ids`.

## Как добавлять новые статьи (Сценарист / Штаб)

1. Положить md-файл в `content/<папка>/дзен-ГГГГ-ММ-ДД….md` в обычном формате:
   ```
   ==================================================
   ДЗЕН · 29.10 · 08:00 · «Было — стало»
   Вопрос читателя: «…»
   Заголовок: …
   Обложка: картинки/dzen-2026-10-29-slug.jpg (промпт …)
   ==================================================

   Текст абзацами через пустую строку. ## Подзаголовки. Списки «- …» или «1. …».

   [картинка внутрь: картинки/dzen-2026-10-29-slug-vnutri.jpg (промпт …)]
   ```
   Если в шапке нет даты (`ДЗЕН · 08:00 · …`), дата берётся из имени файла. Картинки — в `картинки/` рядом с md.
2. `cd tools/dzen-rss && python3 build.py` — смотреть список «Нет картинок». Картинка внутрь, которой нет, выкидывается из текста; без обложки статья не пройдёт `validate.py`. Добавили картинку — запустить `build.py` ещё раз.
3. Проверка на любой момент: `python3 render.py --now 2026-10-30T20:00 --out /tmp/dzen-check --base-url https://<логин>.github.io/ && python3 validate.py --out /tmp/dzen-check --base-url https://<логин>.github.io/ --now 2026-10-30T20:00`.
4. `python3 -m unittest discover -s tests` и залить изменения (`data/`) в репозиторий (с «ок» Макса). Дальше робот сам выпускает статьи по слотам.

Правки уже вышедшей статьи: исправить md → `build.py` → залить. Дзен подхватывает правки 7 дней после первой загрузки.

## Ограничения и что помнить

- `data/articles.json` лежит в публичном репозитории: будущие статьи технически можно прочитать на GitHub до выхода. На сайте и в ленте их нет.
- GitHub запускает расписание с задержкой до ~30 минут, иногда больше. Статья 08:00 может выйти в 08:20.
- Если `validate.py` находит ошибку (например, нет обложки у вышедшей статьи), робот ничего не коммитит и запуск краснеет — GitHub пришлёт письмо. Лента остаётся прежней, пока не починят.
- Обложки сейчас квадратные 1024×1024: требование ≥480×320 выполнено, но Дзен может кадрировать их под горизонталь.
- Будущий `pubDate` мы не используем: в ленте только уже вышедшие статьи, это совпадает с правилом Дзена «pubDate = реальное время публикации на сайте».
